# 관리자 화면

관리자 주소는 `/admin`입니다. 화면은 한국어로 제공하며, 메뉴 데이터는 한국어·영어·중국어 간체·중국어 번체를 편집합니다. 손님 메뉴판과 관리자는 별도 코드 청크로 로드됩니다.

## 계정과 로그인

1. 프로젝트의 Supabase 대시보드에서 **Authentication → Users → Add user → Create new user**를 엽니다.
2. 사용할 이메일과 비밀번호를 직접 입력해 앱 계정을 생성합니다. 이메일 확인이 완료된 계정을 사용합니다.
3. 로컬의 `http://localhost:5173/admin` 또는 배포 주소의 `/admin`에서 직접 로그인합니다.

이 프로젝트에서는 영구 앱 계정이 모두 관리자입니다. 회원가입 화면은 없으며 공개 회원가입·익명 로그인을 계속 비활성화합니다. 비밀번호나 secret/service role key를 저장소·채팅에 기록하지 않습니다. 앱 계정은 사용자가 직접 생성하며, Supabase 대시보드 로그인 계정과 구분합니다.

관리자 클라이언트는 `qr-menu-admin-auth` 저장 키로 로그인 상태를 유지하고 토큰을 갱신합니다. 로그아웃은 이 기기의 세션을 종료합니다. 손님 메뉴판은 별도 클라이언트를 사용하며 관리자 세션을 사용하지 않습니다. UI 로그인 검사는 편집 화면의 진입 조건이며, 실제 조회·변경 권한은 Supabase RLS가 검사합니다.

## 메뉴 관리

- 이름으로 검색하고 카테고리·판매 상태로 필터링합니다.
- 목록에서 판매 중·품절·숨김 상태를 바로 바꿉니다. 숨김 메뉴도 관리자 목록에는 표시합니다.
- 등록·수정 창에서 카테고리, 원화 가격 한 개, 정렬 순서, 네 언어 이름·설명, 사진, 원산지, 알레르기 코드·검수 상태를 편집합니다.
- 숨김 초안은 한국어 이름과 가격·카테고리를 갖추면 저장할 수 있습니다. 판매 중·품절 공개에는 네 언어 이름·설명이 모두 필요합니다.
- 삭제는 확인 창에서 최종 선택합니다. 공개만 중단하려면 숨김 상태를 사용합니다.

저장 결과는 손님 메뉴판의 다음 조회에 반영됩니다. 관리자의 **메뉴판 보기**는 새 탭으로 열립니다. 손님 화면은 최초 접속·새로고침·탭 재활성화 시 조회합니다.

## 카테고리 관리

카테고리 관리 탭에서 네 언어 이름과 정렬 순서를 등록·수정합니다. 작은 정렬 숫자가 앞에 표시됩니다. 메뉴가 남아 있는 카테고리는 삭제 버튼이 비활성화되며, DB 외래 키도 삭제를 막습니다. 숨김 메뉴를 포함해 모든 메뉴를 다른 카테고리로 이동한 뒤 삭제합니다.

## 사진

JPG·PNG·WebP 파일을 최대 5MiB까지 선택합니다. 선택 즉시 미리보기를 보여주고 **메뉴 저장** 때 `menu-images` 버킷으로 업로드합니다. 기존 정적 `/images/…` 경로와 HTTPS 사진 주소도 사용할 수 있습니다.

새 파일은 UUID 경로로 저장하며 기존 파일을 덮어쓰지 않습니다. 메뉴 저장 실패 후 같은 창에서 재시도하면 이미 업로드한 파일을 재사용합니다. 사진 연결을 없애거나 메뉴를 삭제해도 기존 파일 자체는 삭제하지 않습니다. 업로드 후 저장을 취소한 경우를 포함해 사용하지 않는 파일은 Storage 대시보드에서 정리합니다.

## 변경 충돌과 오류

메뉴·카테고리의 수정·삭제 요청에는 조회 시점의 `id`와 `version`을 함께 보냅니다. 대상 행이 없으면 충돌로 안내하고 편집 입력은 유지합니다. 창을 닫고 최신 목록을 불러온 뒤 변경을 다시 적용합니다. 충돌한 내용을 자동으로 덮어쓰지 않습니다.

저장 중에는 중복 저장과 창 닫기를 막습니다. 변경이 있는 창을 닫으면 수정 폐기 확인을 표시하고, 페이지 이탈에도 브라우저 확인을 요청합니다. 목록 조회는 15초, DB 변경은 20초 제한을 적용합니다. 네트워크 오류로 저장 결과가 불확실한 경우 목록을 새로 불러와 먼저 확인합니다. 새 항목 UUID를 창 안에서 유지하므로 재시도로 같은 메뉴가 중복 생성되지는 않습니다.

## Data API 계약

| 동작 | 요청 | 조건 |
| --- | --- | --- |
| 관리 목록 | `GET /rest/v1/categories`, `GET /rest/v1/menu_items` | 모든 상태, `version` 포함 |
| 등록 | `POST /rest/v1/categories`, `POST /rest/v1/menu_items` | 클라이언트 UUID, 쓰기 허용 컬럼만 |
| 수정·상태 변경 | `PATCH /rest/v1/{table}` | `id=eq.…&version=eq.…`, 변경 행 반환 |
| 삭제 | `DELETE /rest/v1/{table}` | `id=eq.…&version=eq.…`, 삭제 ID 반환 |
| 사진 업로드 | Storage SDK `upload()` | `menu-images`, `upsert: false` |

요청에는 publishable key와 로그인 세션을 사용합니다. 서버 관리자 키는 사용하지 않습니다. 등록·수정 요청은 생성·수정 시각과 `version`을 지정하지 않으며 DB 기본값·트리거를 사용합니다. 분류 삭제 충돌, 필수 번역·가격 제약, 권한 실패, 버전 충돌은 한국어로 안내합니다.

## 검증 범위

단위·컴포넌트 테스트는 인증 상태 전환, 익명 계정 차단, 편집·삭제·충돌·사진 재시도를 모의 Auth/HTTP/저장소로 검증합니다. 브라우저에서는 별도 임시 메모리 저장소 미리보기로 모바일과 데스크톱의 편집 화면을 확인했습니다. 임시 미리보기 파일은 저장소와 빌드에 포함하지 않습니다.

실제 프로젝트에는 사진 버킷과 RLS를 적용했고, 권한 SQL 검증은 롤백 후 `PASS`를 확인했습니다. 사용자 계정 생성·로그인과 실제 사진 파일 업로드·메뉴 저장 확인은 사용자가 직접 진행합니다. 운영 메뉴의 기존 값은 이 화면 검증 과정에서 변경하지 않았습니다.
